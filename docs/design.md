# review-notes 設計

review-companion 用の、自作の VS Code レビューコメント拡張と、AI が書き込む CLI。AI（review-companion）が解説カードと返信を置き、利用者が行に問いを書く。

## 求めること

- AI が書いたら通知を出し、［開く］でそのスレッドへ飛ぶ
- スレッドは「誰の番か」で開閉を決めて作る
- AI 側はリポジトリからの相対パスと行で書き、URI は拡張が VS Code の API で作る（URI の形が VS Code の正規形と一字でも違うとスレッドが出ない。`@` など）
- カードに順番を持たせ、「次のカード」で一覧の順に読み進める
- どこまで読んだかを、カードの既読、ツリーのチェック、ファイルのバッジで示す
- ファイルに書くので、VS Code が開いていなくても（セットアップ中でも）カードを置ける
- ログを worktree の git ディレクトリに置くので、`git worktree remove` で一緒に消え、作り直した worktree に前回のコメントが戻らない

## 保存と書き込み

- ファイル: リポジトリの git ディレクトリ（`git rev-parse --absolute-git-dir`。worktree なら `<main>/.git/worktrees/<name>/`）の `review-notes.jsonl`
- パスの基準: `git rev-parse --show-toplevel`（CLI と拡張の両方）。VS Code でサブフォルダを開いていても、同じリポジトリなら同じログを1つだけ見る
- 形式: 1行1イベントの追記ログ。書き手は拡張（人の操作）と CLI（AI）。どちらも追記するだけで、書き換え・削除はしない
  - 追記の前に、ファイルの最後が改行でなければ改行を足す（途中で止まった行に次の行がくっつかないように）
  - 読むときは、改行で終わっていない最後の断片は「書き込み中」とみなして読まない。JSON として読めない行は飛ばす
  - APFS で、別プロセスからの同時追記（1行約100KB × 600行）が混ざらないことを確かめた（2026-10-30）
- イベント（共通: `id`、`at`（ISO 時刻）、`by`（`human` / `agent`））:
  - `add`: 新しいスレッド。`path`（リポジトリからの相対パス）、`line`（1 始まり）、`body`、任意で `card`（カードの順番、1 から）と `side`（`old` なら差分の古い側。無ければ新しい側）
  - `reply`: `thread`（親の id）、`body`
  - `resolve` / `reopen`: `thread`
  - `read` / `unread`: `thread`（カードの既読）
  - `focus`: `thread`（AI が「ここを開いて」と頼む）
- 状態は、ログを頭から畳み込んで作る（`fold(events) → threads`）。親の無いイベントは無視する

## CLI（`review-notes`、AI が使う）

拡張に同梱する Node スクリプト。`--workspace <dir>` で対象のリポジトリ（worktree）を指す。

- `post <entries.json>`: エントリの配列をまとめて1回で追記する。エントリは `{path, line, body, card?, side?}`（新しいスレッド）か `{reply_to, body}`（返信）。`side: 'old'` は差分の古い側（HEAD = merge-base）で、`path` は HEAD にあればよい（PR で消えたファイルにも置ける）。`side` が `old` / `new` 以外、新しい側で `<toplevel>/<path>` が無い、古い側で `HEAD:<path>` が無い、`reply_to` のスレッドが無い、などのエントリは書かずに `{error}` にする。stdout は入力順の `[{id} | {error}]`、exit は 0 = 全件、1 = 一部失敗、2 = 使い方の誤り
- `focus --thread <id>`
- `archive --label <ラベル>`: ログを `review-notes.<ラベル>.jsonl` に名前を変えて退避する（無ければ何もしない）。review-companion は、PR に新しい push があって head が変わったとき、前回の head をラベルにして呼び、カードを置き直す。前回の問いは画面から消えるが、ファイルには残る
- `list [--unanswered]`: 畳み込んだスレッドを JSON で出す。`--unanswered` は、解決されておらず最後の書き込みが human のもの
- 本文は JSON の中に入れる（review-companion は今と同じく `jq --rawfile` で組み立てる）。シェルの引数に載せない

## 拡張の振る舞い

1. 起動時（`onStartupFinished`）に、各ワークスペースフォルダのリポジトリを調べ、git ディレクトリごとに1つだけ見張る。`fs.watchFile`（750ms）。ファイルが無くても見張り始め、作られたら読む
2. 「どこまで見たか」を VS Code の workspaceState に、ログのパスごとに `{count, lastId}` で持つ。ログが追記だけなので、先頭 count 件が既読。`lastId` が合わなければ（ログが作り直された）0 件から数える
   - 再読み込みしても、同じ書き込みで通知が鳴らない
   - VS Code を開く前に AI が書いたものも、初めて開いたときに1回だけ知らせる（セットアップ中にカードを置く流れに合う）
   - `archive` でログが退避・作り直されたら、`lastId` が合わないので描き直し、新しいカードを1回だけ知らせる。古いスレッドは消える
3. 新しく見た AI の `add` / `reply` は、2秒新しい書き込みが無くなってから1つの通知にまとめる。1件なら「AI が <path>:<line> に返信しました」/「コメントしました」、複数なら「AI が N 件書き込みました」。［開く］で1件目のスレッドへ
4. 新しく見た `focus` のうち最後の1つへ移動する（通知なし）
5. スレッドの開閉:
   - 新しく作るスレッドは、未解決で最後が agent なら開く（読む番）。解決済みか、最後が human（AI の返信待ち）なら閉じる
   - 既にあるスレッドの開閉は触らない。ただし AI の返信が新しく付いたら開く（読む番になった）
   - 開くときは「閉じる → 開く」の順に設定する（拡張側の値が変わらないと VS Code が反映しないため。人が閉じたスレッドでも開く）
6. スレッドは `line` の1行に付く（カードがコードより先に読めるように）。付けられるのは、見張っているリポジトリの中の `file:` の文書（新しい側）と、git 拡張が作業ツリーの差分で開く古い側の `git:` の文書（ref が `~` = index か `HEAD`）。review 用 worktree は mixed reset なので、どちらも merge-base の内容になる。それ以外の `git:`（履歴やマージの各段）には付けない
   - 古い側のスレッドは `side: 'old'` だけを持ち、ref は持たない。表示先の URI は git 拡張と同じ形（`git:` + `{"path","ref"}` の query）で組み立て、作業ツリーにファイルがあれば `~`（変更のある差分の左側）、無ければ `HEAD`（削除されたファイル）にする。URI が一字でも違うとスレッドが出ないため
   - 差分の左側はアクティブなエディタにならないので、移動は見えているエディタから URI で探す
7. 人の操作: スレッドの作成と返信（ボタンは状態ごとに1つにして、Cmd+Enter で送れるようにする）、Resolve / Reopen、カードの既読・未読。人が作ったスレッドは、VS Code が作った入力用のスレッドをそのまま使い続ける（作り直すと閉じた状態で出てしまう）。書いたらすぐ画面に反映する（見張りを待たない）
8. 移動先: 差分（`git.openChange`。HEAD が merge-base なので PR の差分になる）を開いて、その行へ。設定で普通のエディタにも切り替えられる
9. カードの順: 「次のカード」「前のカード」「次の未読カード」（末尾まで行ったら先頭へ戻る）。今のカードは「カーソル行にあるカード」、無ければ「最後にコマンドで着いたカード」。「次のカード」で離れたカードは既読にする。1ファイルの中のスレッド間の移動は VS Code 標準の Alt+F9 / Shift+Alt+F9 に任せる
10. カードのツリー: ソース管理のサイドバーにビュー「Review Notes」を置く（変更ファイルの一覧の隣）。カードを順に並べ、ラベルは「#K path:L — 本文の冒頭」。各項目に既読のチェックボックス（外せば未読に戻る）。押すとそのカードへ。「既読を隠す」を切り替えられる
11. ファイルのバッジ: 未読カードがあるファイルに未読数（最大 `99`）。エクスプローラーとソース管理の一覧に出る
12. ステータスバー: 「カード 未読 N / 全 M」。押すと「次の未読カード」へ
13. 書き込めなかったとき（git ディレクトリが無いなど）はエラーを通知する。見張りの読み直しの失敗は黙って次回に回す

## やらないこと

- Marketplace への公開・チーム配布
- 行番号の追従（レビュー用 worktree は編集しない前提）
- 同じ worktree を2つの窓で開いたときの通知の重複の解消（README に書くだけ）
- review-companion の載せ替え（別の計画にする。CLI の `post` は今の `relay-post.mjs` に近い入出力（エントリの配列 → `[{id} | {error}]`）にしてあるので、差し替えは小さい）
